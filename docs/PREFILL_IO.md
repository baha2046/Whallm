# 分開 Prefill／Decode 讀取

2026-09-15 工作目錄的正式功能，三模型預設啟用。尚未重新打包或發布。

## 行為

- DeepSeek V4、V4.1、Qwen 的主模型，以及 DSpark／MTP 配套模型，共用 `PrefillReader`。
- Prefill 使用每層獨立的檔案連線，設定 macOS `F_NOCACHE` 與關閉 read-ahead。整層讀取明確使用此連線，一般分批 Prefill 依請求階段選擇它。
- Decode 保留原本的檔案連線與專家快取；預設仍使用系統頁面快取。此功能不改路由、權重排列或模型計算。
- 檔案位置、長度和每個目的區段均符合記憶體頁面對齊時，直接讀入模型緩衝區。其他情況先讀到對齊暫存區，再按原權重格式複製。Qwen、V4.1 不需要重新安裝模型。
- 每個讀取工作者最多保留一個「單專家大小加兩頁」的暫存區；已對齊的直接路徑不配置暫存區。分段讀取使用另一組工作者，兩組各自有界。
- 讀取錯誤或取消請求時，沿用等待背景讀取結束的收尾流程。模型關閉會先等待工作者，再關閉暫存區和兩組檔案連線；初始化失敗會關閉已開啟的連線。
- 缺少必要資料會報錯；檔案尾端不必有額外補齊頁面。遇到不能安全續讀的未對齊短讀會報錯。

`F_NOCACHE` 是作業系統的快取策略，不代表已清空既有頁面，也不保證每個位元組都實際經過 SSD。

## 設定與相容性

| 入口 | 設定 |
| --- | --- |
| App | 三模型自動啟用；不新增進階調整項 |
| CLI／Server 命令列 | `--separate-prefill-io`；以 `--no-separate-prefill-io` 關閉 |
| Server 模型設定 | `separate_prefill_io: true`；舊設定省略此欄位也預設啟用 |
| 診斷 | CLI metrics 的 `prefill_io` 含直接／複製的有效資料量與暫存配置；不是實體 SSD 流量 |

既有 `expert_file_cache_policy` 在本功能開啟時控制 Decode；關閉分開讀取後，沿用原本全階段的 cached／bypass 行為。
路由感知快取仍由 `expert_eviction_policy=route` 選擇，與本功能獨立。

## 驗證範圍

三種正式 expert blob 格式皆測過整層與逐專家讀取，包含權重每個區段的位元組比對、Prefill／Decode 連線隔離、檔案尾端、短讀、取消、初始化失敗和關閉。一般與整層 Prefill 的取消測試也啟用分開讀取。
V4.1 尚無完整 checkpoint，不能把格式測試當成完整模型生成驗收。

本輪 Python 395 項、Swift 93 項通過。
[完整模型對照與原始資料](benchmarks/2026-09-15-prefill-io/README.md)：
V4 4K 首字 −10.95%、整次 −4.63%；Qwen 首字 +0.73%、整次 −1.08%，整體接近持平。
各兩輪、128 個輸出 tokens；輸出一致且無新增 swapout。

# Qwen 排序提示候選：任務正確率門檻

使用者於 2026-09-06 決定：**任務正確率不下降**。允許措辭不同，沒有授權任何品質退步。
此門檻用於會改變文字的 `sorted_indices=True` 研究候選；原版作為對照。
無提示候選的精確輸出驗證繼續使用自己的條件，不因本決定放寬。

## 判定規則

- 程式、數學、繁中理解、工具使用分開報告正確率，不互相抵銷。
- 題目、答案、評分器與生成設定必須在看候選回答前固定並保存 hash。
  題目不能用於調整候選；改候選後須使用新的保留題組。
- 列出原版對／候選錯、原版錯／候選對、兩者皆對、兩者皆錯。
  初測遇到原版對／候選錯即停止並診斷；這是保守停止規則，不聲稱單題可估計整體退步比例。
- 有遺漏、截斷、評分爭議或執行失敗都不能算通過。評分器修正時，兩版本一併重評，保存原因。
- 小題組零退步只可進入下一階段。有限樣本不能保證所有任務永遠不退步；
  正式評估需報告各類配對正確率差與不確定範圍，不能把「沒有顯著差異」當成「沒有退步」。
  嚴格零退步的統計條件若證據不足，標記未定，不自行引入可容忍下降幅度。
- 速度、記憶體、長輸入、較長生成及 prompt-cache 合約須另外通過，品質分數不能取代它們。
  未完成採用條件前，不整合成 runtime 預設。

## Q0：固定答案初測（下一步）

使用 [12 題固定題組](../docs/benchmarks/prompts/2026-09-06-qwen-task-accuracy.json)，每類三題。
這是新編合成題，不是公開基準成績，也未經獨立出題審查。
程式題檢查程式理解；數學檢查確定答案；繁中檢查給定文字的推論；工具題檢查 JSON 名稱與參數。
程式生成、長篇繁中回答、多步工具呼叫均不在本階段範圍。

評分為完整 JSON 結構與值相等，允許空白和物件鍵順序不同；
拒絕重複鍵、額外文字、缺少或多餘欄位，以及錯誤型別。每題整體計一分。
所有題目要求 JSON，因此同時測答案正確與遵循格式，不視為純能力分數。

對照與候選使用同一 installed model／tokenizer，Slot 4096、MTP false、thinking false、greedy。
輸入固定 1024 tokens，使用明確標示的無關填充；生成上限 128 tokens。
每個 request 使用獨立 process，停用 persistent prompt cache，OS page cache 不清空。
題目交替 control→candidate 與 candidate→control，不同 GPU 測試不並行。
每次候選預期經過 192 次 Prefill expert 呼叫（48 layers × 4 個 attention chunks），
且排序提示為開啟，依 metrics 核對實際計數。
保存全部 rendered prompts、回答、token hashes、metrics、命令、來源 hashes 與啟動前規則快照。
本階段時間僅供診斷，不構成正式速度結論。

執行：

```sh
PYTHONPATH=runtime:Scripts .venv/bin/python Scripts/benchmark_qwen_task_accuracy.py \
  --suite docs/benchmarks/prompts/2026-09-06-qwen-task-accuracy.json \
  --output scratch/qwen-task-accuracy-2026-09-06-v2
```

Q0 若沒有退步，下一步先建立更大、獨立的題組與評分合約：
程式須實際跑功能測試；數學須答案可核對；繁中涵蓋理解、指令與長回答；
工具須涵蓋選工具、schema、參數和多步狀態。
程式執行須隔離，人工評分須隱去版本，並事先固定評分規則與處理歧義的方法。
